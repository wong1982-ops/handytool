# Job Radar — Design Document

**Date:** 2026-03-18
**Status:** Approved for implementation
**Route:** `/tools/job-radar`

---

## 1. Understanding Summary

- **What**: A public job aggregator tool on toolk1t that collects two categories of jobs from AU and NZ job boards daily — **IT/Tech** roles and **French language** roles (jobs requiring French skills) — deduplicates across sources, and presents them in a tabbed, filterable, sortable gallery with drill-in detail views
- **Why**: Give job seekers a single place to browse AU/NZ tech jobs and French language jobs across multiple platforms without visiting each one
- **Who**: Any public visitor to toolk1t — no auth required to browse
- **Sources**: Seek (AU+NZ), Indeed (AU+NZ), LinkedIn Jobs, Trade Me Jobs (NZ) — prefer official APIs, scrape only as last resort
- **Key constraints**: Staggered daily cron per source, normalised deduplication (title + company + fuzzy location), rate-limited API (60 req/min per IP), mobile-first responsive design, respect robots.txt and API ToS
- **Non-goals**: No user accounts/saved jobs, no AI salary estimation, no real-time scraping — batch only

## 2. Assumptions

1. Seek API requires a partner application — may need to start with scraping or skip until approved
2. LinkedIn is the hardest to scrape legally — may need to defer or use their limited job search API
3. Under 1,000 active jobs — single Supabase table with proper indexing is sufficient
4. Salary data shown only when provided by source — "Not disclosed" label otherwise
5. Job retention: active for display, archived to separate table after 90 days, never deleted
6. Deduplication runs at ingestion time, not retroactively
7. No credits consumed — this is a free public tool
8. Conservative scraping for Trade Me (respect robots.txt, low frequency, public listings only)

## 3. Database Schema

### `jobs` table

| Column | Type | Notes |
|---|---|---|
| `id` | uuid (PK) | Auto-generated |
| `source` | text | `seek`, `indeed`, `linkedin`, `trademe` |
| `source_id` | text | Original job ID from source |
| `source_url` | text | Link to original posting |
| `title` | text | Job title as posted |
| `title_normalised` | text | Lowercase, trimmed, synonyms unified (for dedup) |
| `company` | text | Company name |
| `company_normalised` | text | Lowercase, trimmed (for dedup) |
| `location` | text | Original location string |
| `location_normalised` | text | Mapped to standard city/region (for dedup + filtering) |
| `category` | text | `it` or `french` — job category for tab filtering |
| `country` | text | `AU` or `NZ` |
| `employment_type` | text | `full-time`, `contract`, `part-time` |
| `work_mode` | text | `remote`, `hybrid`, `onsite` |
| `salary_min` | integer | Annual salary floor (nullable) |
| `salary_max` | integer | Annual salary ceiling (nullable) |
| `hourly_rate_min` | numeric | For contracts (nullable) |
| `hourly_rate_max` | numeric | For contracts (nullable) |
| `salary_currency` | text | `AUD` or `NZD` |
| `description` | text | Job description snippet/summary |
| `tags` | text[] | Extracted tech keywords (e.g. `['React', 'Node.js']`) |
| `posted_at` | timestamptz | When the job was posted on source |
| `scraped_at` | timestamptz | When we collected it |
| `is_active` | boolean | `true` until archived |
| `created_at` | timestamptz | Row creation time |

### Indexes

- `(title_normalised, company_normalised, location_normalised)` — dedup lookup
- `(category, is_active, posted_at DESC)` — gallery default sort (scoped by tab)
- `(employment_type)`, `(work_mode)`, `(country)` — filter queries

### `jobs_archive` table

Same schema as `jobs`. Rows moved here via weekly cron after 90 days.

## 4. Cron Jobs & Scraper Architecture

### Vercel Cron Schedule (staggered, AEST)

| Time (UTC) | Route | Source |
|---|---|---|
| 19:00 (5:00 AM AEST) | `/api/cron/scrape-jobs/seek` | Seek AU + NZ |
| 19:15 (5:15 AM AEST) | `/api/cron/scrape-jobs/indeed` | Indeed AU + NZ |
| 19:30 (5:30 AM AEST) | `/api/cron/scrape-jobs/linkedin` | LinkedIn Jobs |
| 19:45 (5:45 AM AEST) | `/api/cron/scrape-jobs/trademe` | Trade Me Jobs NZ |
| 20:00 (6:00 AM AEST, Sunday) | `/api/cron/archive-jobs` | Archive 90d+ jobs |

### File Structure

```
lib/jobs/
├── scrapers/
│   ├── types.ts          # RawJob interface (common shape before normalisation)
│   ├── seek.ts           # Seek adapter
│   ├── indeed.ts         # Indeed adapter
│   ├── linkedin.ts       # LinkedIn adapter
│   └── trademe.ts        # Trade Me adapter
├── keywords.ts           # Configurable keyword lists for IT and French categories
├── categorise.ts         # Assigns category (it/french) based on keyword matching
├── normalise.ts          # Title/company/location normalisation + employment type parsing
├── dedup.ts              # Check existing rows, return only new unique jobs
├── ingest.ts             # Orchestrator: scrape → normalise → categorise → dedup → insert
└── archive.ts            # Move 90d+ jobs to jobs_archive
```

### Keyword Lists (`keywords.ts`)

Each scraper searches for **both** categories per source. Configurable keyword lists:

- **IT category**: `software engineer`, `developer`, `devops`, `frontend`, `backend`, `fullstack`, `cloud engineer`, `data engineer`, `QA`, `sysadmin`, `IT support`, `security analyst`, `network engineer`, etc.
- **French category**: `french speaking`, `french language`, `bilingual french`, `french teacher`, `french translator`, `francophone`, etc.

A job matching both categories is assigned to **both** (inserted twice with different `category` values). This is expected to be rare.

### Ingestion Flow (per cron run)

1. Cron route validates `x-cron-secret` header
2. Calls source-specific scraper → returns `RawJob[]`
3. Normalises each job (lowercase titles, map locations to standard cities, detect employment type + work mode from description)
4. Assigns `category` — `it` or `french` — based on keyword matching against configurable keyword lists
5. Dedup check against `jobs` table using normalised fields (scoped by category)
5. Bulk insert new jobs into Supabase
6. Log scrape stats (total found, new inserted, duplicates skipped)

## 5. Deduplication Logic

### Normalisation Rules

| Field | Logic |
|---|---|
| **Title** | Lowercase, trim whitespace, remove level prefixes ("Senior ", "Junior ", "Lead "), unify synonyms ("Software Engineer" = "Software Developer", "Frontend" = "Front-end" = "Front End") |
| **Company** | Lowercase, trim, remove suffixes ("Pty Ltd", "Ltd", "Inc", "Limited"), remove "The " prefix |
| **Location** | Map to standard city names (e.g. "Sydney CBD" → "Sydney", "Christchurch Central" → "Christchurch"), strip postcodes |

### Dedup Flow

1. Normalise incoming job
2. Query: `WHERE title_normalised = X AND company_normalised = Y AND location_normalised = Z AND category = C AND is_active = true`
3. Match found → skip insert
4. No match → insert as new job

Same job from multiple sources — first source wins, later duplicates are skipped entirely.

## 6. Gallery API

### `GET /api/v1/jobs`

| Param | Type | Default | Example |
|---|---|---|---|
| `category` | string | `it` | `?category=french` (required — maps to tab) |
| `page` | number | `1` | `?page=2` |
| `limit` | number | `20` | `?limit=10` (max 50) |
| `sort` | string | `posted_at` | `?sort=salary_max` |
| `order` | string | `desc` | `?order=asc` |
| `employment_type` | string | all | `?employment_type=contract` |
| `work_mode` | string | all | `?work_mode=remote` |
| `country` | string | all | `?country=AU` |
| `days` | number | all | `?days=3` |
| `salary_min` | number | - | `?salary_min=100000` |
| `salary_max` | number | - | `?salary_max=200000` |
| `hourly_min` | number | - | `?hourly_min=80` |
| `hourly_max` | number | - | `?hourly_max=150` |
| `q` | string | - | `?q=react` |

### Response Shape

```json
{
  "data": [ { ...job } ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 342,
    "totalPages": 18
  }
}
```

### `GET /api/v1/jobs/:id`

Returns full job record including description.

### Rate Limiting

60 requests/min per IP. Returns `429` when exceeded.

## 7. Frontend

### Route

`app/tools/job-radar/page.tsx`

### Components

```
tools/job-radar/
├── job-radar-page.tsx     # Page shell with two tabs: IT/Tech | French Language
├── job-gallery.tsx        # Main gallery container (filters + list + pagination), receives category prop
├── job-filters.tsx        # Filter bar: employment type, work mode, country, days, salary range
├── job-search-bar.tsx     # Keyword search input
├── job-card.tsx           # Card: title, company, location, tags, salary, badges
├── job-detail-modal.tsx   # Drill-in: summary card + "Apply on [source]" CTA
├── job-pagination.tsx     # Page controls (prev/next + page numbers)
└── types.ts               # Frontend types
```

### Tabs

Two tabs at the top of the gallery:
- **IT / Tech** (default) — all IT/software/tech roles
- **French Language** — roles requiring French language skills (translators, bilingual support, French teachers, etc.)

Switching tabs resets filters and pagination. Active tab is reflected in URL query param (`?category=it` / `?category=french`).

### Layout (Mobile-First)

- **Mobile**: Stacked cards, filters in collapsible drawer/sheet, full-width search bar at top
- **Tablet**: 2-column card grid, filters as horizontal pills
- **Desktop**: Sidebar filters on left, 2-3 column card grid on right

### Job Card

- Job title (bold)
- Company name + location (city, country flag)
- Badges: `Full-time` / `Contract`, `Remote` / `Hybrid` / `Onsite`
- Salary/rate if available, "Not disclosed" otherwise
- Posted date (relative: "2 days ago")
- Source icon (Seek/Indeed/LinkedIn/Trade Me)

### Job Detail Modal

- Slide-up on mobile, modal on desktop
- All card fields + description summary
- Tech tags as pills
- "Apply on [Source]" primary CTA button → `source_url`
- "Share" secondary action

### Filter Behaviour

- Filters update URL query params (shareable/bookmarkable)
- Debounced search input (300ms)
- "Clear all filters" button when any filter is active

## 8. Error Handling & Resilience

### Scraper Failures

- Each source runs independently — one failing doesn't block others
- On failure: log error with source name + error message, continue silently
- No retry on same run — next day's cron picks up new jobs

### Scraper Timeouts

- Each scraper limits to first 2-3 pages of results per run
- If timeout approaches, insert whatever was collected so far

### API Errors

- `400` — invalid filter params (Zod validation)
- `404` — job not found
- `429` — rate limit exceeded
- `500` — unexpected server error

### Data Quality

- Jobs missing both title AND company are discarded at ingestion
- Empty salary fields left null (never zero)
- `posted_at` falls back to `scraped_at` if source doesn't provide a post date

## 9. Decision Log

| # | Decision | Alternatives Considered | Why |
|---|---|---|---|
| 1 | Seek, Indeed, LinkedIn, Trade Me as sources | RSS feeds, third-party aggregator APIs | Best AU/NZ coverage for tech roles |
| 2 | APIs first, scrape as fallback | Scrape-only, API-only | Balances legality with coverage |
| 3 | Conservative scraping for Trade Me | Skip Trade Me, aggressive scraping | Respects robots.txt, covers NZ market |
| 4 | Normalised fuzzy dedup (title + company + location) | Exact match, AI similarity scoring | Good accuracy without LLM cost |
| 5 | Skip duplicates entirely (no tracking) | Store duplicates with FK pointer | Simpler, no value in tracking dupes at this scale |
| 6 | Vercel cron + Next.js API routes | External Lambda, third-party aggregator | Zero new infra, fits existing stack |
| 7 | Staggered per-source cron (5am/5:15/5:30/5:45 AEST) | Single daily run, twice daily | Spreads load, isolates failures |
| 8 | `jobs` + `jobs_archive` tables | Single table, soft-delete only | Keeps active table lean, never loses data |
| 9 | 90-day archive threshold | 30 days, indefinite | Balance of recency and history |
| 10 | Salary: show when available, "Not disclosed" otherwise | AI estimation, blank | Honest, no misleading data |
| 11 | Summary card + "Apply on source" CTA | Full detail page, redirect only | Shows value on platform, drives traffic to source |
| 12 | Public, no auth, rate-limited (60 req/min/IP) | Auth-gated, fully open | Accessible but protected |
| 13 | Configurable keyword list for role scope | Fixed developer only, all IT | Flexible, start broad with all IT |
| 14 | URL slug: `/tools/job-radar` | `tech-jobs`, `job-board`, `job-hunter` | Distinctive, memorable |
| 15 | Mobile-first responsive | Desktop-first, desktop-only | Critical for job seekers on mobile |
| 16 | Two categories: IT + French Language as tabs | Mixed in one list with filter, separate tool pages | Clean separation, shared infrastructure, easy to browse |
| 17 | Jobs matching both categories inserted twice | Single row with multi-category column | Simpler queries, clean tab separation, rare overlap |
