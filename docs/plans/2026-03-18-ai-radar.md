# AI Radar — Design Document

**Date:** 2026-03-18
**Status:** Approved for implementation
**Route:** `/tools/ai-radar`

---

## 1. Understanding Summary

- **What**: A public AI model tracker on toolk1t that collects news about new AI model releases and major updates daily, showing what each model can do and what problems it solves, presented in a categorised tabbed feed
- **Why**: Help technical practitioners stay current on the rapidly evolving AI model landscape without tracking dozens of sources
- **Who**: Public visitors to toolk1t — curated for a technical audience that understands ML/AI concepts
- **Scope**: New model releases + major updates to existing models (e.g. new capabilities, modality additions). NOT general AI industry news, tutorials, or opinion pieces
- **Sources**: Mix of news sites (TechCrunch AI, The Verge, VentureBeat, Ars Technica), research feeds (arXiv, Hugging Face blog), provider blogs (OpenAI, Anthropic, Google AI, Meta AI), and community (Hacker News, Reddit r/MachineLearning)
- **Content**: Headline + 2-3 sentence summary of capabilities/what it solves + link to original
- **Categories (tabs)**: All, LLMs, Image/Video Generation, Audio/Speech, Code Models, Multimodal, Embedding/Search, Robotics/Agents
- **Key constraints**: Daily cron, normalised dedup (first source wins), 90-day archive, rate-limited, mobile-first
- **Non-goals**: No user accounts, no full articles, no AI-generated summaries, no bookmarking, no general AI industry news

## 2. Assumptions

1. RSS feeds are available for most sources — primary collection method
2. Some sources (Reddit, HN) require API access
3. ~20-50 items per day across all categories
4. Summaries extracted from RSS feed descriptions — no LLM-generated summaries
5. Category assignment based on keywords in title/description at ingestion time
6. A model appearing in multiple sources — first source wins, duplicates skipped
7. Free public tool, no credits consumed
8. 7 category tabs — some tabs may have few items on quiet days, acceptable
9. Content filtered at ingestion: only model-related announcements kept, general AI news discarded

## 3. Database Schema

### `ai_news` table

| Column | Type | Notes |
|---|---|---|
| `id` | uuid (PK) | Auto-generated |
| `source` | text | e.g. `techcrunch`, `theverge`, `arxiv`, `huggingface`, `openai_blog`, `anthropic_blog`, `google_blog`, `meta_blog`, `hackernews`, `reddit` |
| `source_id` | text | Original article ID or URL hash |
| `source_url` | text | Link to original article |
| `title` | text | Headline as published |
| `title_normalised` | text | Lowercase, trimmed (for dedup) |
| `summary` | text | 2-3 sentence summary of capabilities/what it solves |
| `category` | text | `llms`, `image-video`, `audio-speech`, `code-models`, `multimodal`, `embedding-search`, `robotics-agents` |
| `model_name` | text | Extracted model name if identifiable (e.g. "GPT-5", "Llama 4") — nullable |
| `provider` | text | Model provider if identifiable (e.g. "OpenAI", "Meta") — nullable |
| `tags` | text[] | Additional keywords (e.g. `['reasoning', 'benchmark', 'open-source']`) |
| `image_url` | text | Thumbnail/OG image URL from source — nullable |
| `posted_at` | timestamptz | Original publish date |
| `scraped_at` | timestamptz | When we collected it |
| `is_active` | boolean | `true` until archived |
| `created_at` | timestamptz | Row creation time |

### Indexes

- `(title_normalised)` — dedup lookup
- `(category, is_active, posted_at DESC)` — gallery sort per tab
- `(is_active, posted_at DESC)` — "All" feed sort

### `ai_news_archive` table

Same schema as `ai_news`. Rows moved here via weekly cron after 90 days.

## 4. Cron Jobs & Collector Architecture

### Vercel Cron Schedule

| Time (UTC) | Route | Source Group |
|---|---|---|
| 18:00 (4:00 AM AEST) | `/api/cron/collect-ai-news/rss` | RSS feeds (TechCrunch, The Verge, VentureBeat, Ars Technica, arXiv, Hugging Face, OpenAI, Anthropic, Google AI, Meta AI blogs) |
| 18:15 (4:15 AM AEST) | `/api/cron/collect-ai-news/community` | Community (Hacker News, Reddit r/MachineLearning) |
| 20:00 (6:00 AM AEST, Sunday) | `/api/cron/archive-ai-news` | Archive 90d+ items |

| Source | Feed URL | Type |
|---|---|---|

### File Structure

```
lib/ai-news/
├── collectors/
│   ├── types.ts           # RawNewsItem interface
│   ├── rss.ts             # Generic RSS feed parser
│   ├── hackernews.ts      # HN API (search for AI model posts)
│   └── reddit.ts          # Reddit API (r/MachineLearning)
├── sources.ts             # List of RSS feed URLs + source metadata
├── categorise.ts          # Assign category based on title/summary keywords
├── normalise.ts           # Title normalisation for dedup
├── filter.ts              # Relevance filtering — only keep model-related items
├── extract.ts             # Model name + provider extraction via regex
├── dedup.ts               # Check existing rows before insert
├── ingest.ts              # Orchestrator: collect → filter → categorise → normalise → dedup → insert
└── archive.ts             # Move 90d+ items to ai_news_archive
```

### Ingestion Flow (per cron run)

1. Cron route validates `x-cron-secret` header
2. For RSS: iterates over all configured feed URLs, parses each feed, extracts items published in the last 48h
3. For community: queries HN/Reddit APIs for AI model-related posts
4. Filters items to only model releases/updates using relevance keywords
5. Assigns category based on title + summary keywords
6. Extracts model name + provider via regex
7. Normalises title for dedup, checks against existing rows
8. Bulk inserts new items
9. Logs stats (total collected, filtered, new inserted, duplicates skipped)

## 5. Category Assignment

### Category Keywords

| Category | Tab Label | Keywords |
|---|---|---|
| `llms` | LLMs | `language model`, `llm`, `gpt`, `claude`, `gemini`, `llama`, `mistral`, `phi`, `qwen`, `chat`, `text generation`, `reasoning model`, `transformer` |
| `image-video` | Image / Video | `image generation`, `video generation`, `diffusion`, `stable diffusion`, `dall-e`, `midjourney`, `flux`, `sora`, `runway`, `imagen`, `text-to-image`, `text-to-video` |
| `audio-speech` | Audio / Speech | `text-to-speech`, `speech-to-text`, `tts`, `stt`, `whisper`, `voice`, `audio model`, `music generation`, `sound` |
| `code-models` | Code Models | `code generation`, `codex`, `copilot`, `code model`, `coding assistant`, `code llm`, `devin`, `cursor` |
| `multimodal` | Multimodal | `multimodal`, `vision-language`, `vlm`, `omni`, `multi-modal`, `any-to-any` |
| `embedding-search` | Embedding / Search | `embedding`, `vector`, `retrieval`, `search model`, `reranker`, `rag`, `semantic search` |
| `robotics-agents` | Robotics / Agents | `robot`, `agent`, `autonomous`, `embodied`, `manipulation`, `navigation`, `planning agent`, `tool use` |

Assignment: match keywords against lowercase title + summary. First matching category wins (ordered by specificity — `code-models` before `llms`). Default to `llms` if no match.

### Relevance Filtering

Only keep items matching these keywords: `model`, `release`, `launch`, `announce`, `update`, `upgrade`, `benchmark`, `capability`, `parameter`, `weights`, `fine-tune`, `open source`, `api`, plus all category keywords above.

### Model Name Extraction

Regex patterns for known model names: `GPT-\d`, `Claude \d`, `Gemini \d`, `Llama \d`, `Mistral`, `Phi-\d`, `DALL-E`, `Stable Diffusion`, `Whisper`, `Codex`, etc. Best-effort, nullable.

## 6. Gallery API

### `GET /api/v1/ai-news`

| Param | Type | Default | Example |
|---|---|---|---|
| `category` | string | all | `?category=llms` |
| `page` | number | `1` | `?page=2` |
| `limit` | number | `20` | `?limit=10` (max 50) |
| `days` | number | all | `?days=7` |
| `q` | string | - | `?q=llama` |

### Response Shape

```json
{
  "data": [ { ...newsItem } ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 156,
    "totalPages": 8
  }
}
```

### `GET /api/v1/ai-news/:id`

Returns full item record.

### Rate Limiting

60 requests/min per IP. Returns `429` when exceeded.

## 7. Frontend

### Route

`app/tools/ai-radar/page.tsx`

### Components

```
tools/ai-radar/
├── ai-radar-page.tsx       # Page shell with 7 category tabs + "All" tab
├── news-feed.tsx           # Feed container (list + pagination), receives category prop
├── news-card.tsx           # Card: title, summary, source, model name, posted date, thumbnail
├── news-detail-modal.tsx   # Drill-in: full summary + tags + "Read original" CTA
├── news-search-bar.tsx     # Keyword search (debounced)
├── news-pagination.tsx     # Page controls (prev/next + page numbers)
└── types.ts                # Frontend types
```

### Tabs

Horizontally scrollable on mobile:
- **All** (default) — all categories in reverse chronological order
- **LLMs**
- **Image / Video**
- **Audio / Speech**
- **Code Models**
- **Multimodal**
- **Embedding / Search**
- **Robotics / Agents**

Switching tabs resets pagination. Active tab reflected in URL `?category=llms`.

### Layout (Mobile-First)

- **Mobile**: Tabs as horizontally scrollable pills, stacked cards below, full-width search bar
- **Tablet**: Same scrollable tabs, 2-column card grid
- **Desktop**: Tabs as a row, 2-3 column card grid

### News Card

- Thumbnail image (if available, left-aligned small)
- Title (bold)
- Summary (2-3 sentences, truncated to 2 lines)
- Model name badge (if identified, e.g. "GPT-5")
- Source label + relative date ("TechCrunch · 2 hours ago")

### News Detail Modal

- Slide-up on mobile, modal on desktop
- Full title + complete summary
- Model name + provider badges
- Tags as pills
- Thumbnail image (larger)
- "Read original" primary CTA → `source_url`
- "Share" secondary action

### Additional Controls

- Days dropdown: Today, Last 3 days, Last 7 days, Last 30 days
- Search bar: debounced 300ms, searches title + tags

## 8. Error Handling & Resilience

### Collector Failures

- RSS group and community group run independently
- Within RSS group: each feed fetched independently — one broken feed doesn't stop others
- On failure: log error with source name, continue to next source
- No retry on same run — next day's cron picks up new items

### Content Filtering

- Not every RSS item is about model releases — filtered at ingestion using relevance keywords
- Items that don't match are discarded silently

### Data Quality

- Items missing title are discarded
- Missing summary: use RSS description field, truncate to 500 chars
- Missing `posted_at`: fall back to `scraped_at`
- Missing image: render card without thumbnail (no placeholder)

## 9. Decision Log

| # | Decision | Alternatives Considered | Why |
|---|---|---|---|
| 1 | Focus on AI model releases/updates only | General AI news, tutorials, opinion | Clear scope, high value for technical audience |
| 2 | RSS feeds + community APIs as sources | Scraping only, third-party aggregator | RSS is reliable, free, legal; community APIs fill gaps |
| 3 | 2 grouped crons (RSS + community) | Per-source crons like Job Radar | Fewer cron slots, RSS feeds are lightweight enough to batch |
| 4 | 7 categories by model type | By provider, by capability, no categories | Model type is most useful for practitioners deciding which tools to use |
| 5 | Tabs per category + "All" tab | Single feed with filter pills | Consistent with Job Radar pattern, clean separation |
| 6 | Normalised title dedup, first source wins | Group related articles, keep all with markers | Simple, proven pattern from Job Radar |
| 7 | Headline + 2-3 sentence summary (from source) | AI-generated summaries, full articles | No LLM cost, respects source content, fast |
| 8 | Keyword-based content filtering at ingestion | Manual curation, AI classification | Zero cost, good enough for filtering model announcements |
| 9 | Model name extraction via regex | NER model, manual tagging | Simple, handles known model naming patterns |
| 10 | 90-day active, then archive | 30 days, indefinite | Consistent with Job Radar, good balance |
| 11 | URL slug: `/tools/ai-radar` | `ai-pulse`, `ai-news`, `ai-digest` | Pairs nicely with `job-radar`, distinctive |
| 12 | Daily cron at 4am AEST | Hourly, twice daily | Sufficient for daily catch-up use case |
| 13 | Public, no auth, rate-limited (60 req/min/IP) | Auth-gated | Consistent with Job Radar |
